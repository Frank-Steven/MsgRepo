# MsgRepo v2 设计文档

> 本文档是 MsgRepo 的现行设计（v2），取代 v1 系列文档（`architecture.md` / `data-model.md` 等，保留作历史参考）。
> 核心理念：**日程表与待办清单的结合是应用本体，消息只是数据源，AI 是可从手机端插拔的处理服务。**
> 文末附修订记录（v2.1：任务时间尺度 + 待办分页 + 日视图缩放 + 交互修正；v2.2：年度粒度视图 + 尺度过滤 + 子任务系统）。

## 0. 总览

```
┌──────────────────────────── 手机端（全部功能）────────────────────────────┐
│  日程(年度/年/月/日四视图)  待办  笔记  消息(数据源)  设置                    │
│  ─────────────────────────────────────────────────────────────            │
│  SQLite(DB v5) · 撤销队列 · 提醒调度 · 通知采集 · AiClient(路由+流式)        │
└──────────────┬───────────────────────────────┬────────────────────────────┘
               │ adb reverse（自动建立）          │ HTTPS（用户配置的远程 API）
┌──────────────▼──────────────┐   ┌─────────────▼─────────────┐
│ 电脑端（纯 AI 服务）          │   │ 远程 OpenAI 兼容 API        │
│ 状态栏菜单应用（Electron）     │   │ （本地 llama.cpp 或其他）    │
│ AI 接口 + 服务管理器 + 自动通道│   └───────────────────────────┘
└─────────────────────────────┘
```

- **手机端**持有全部数据与全部 UI：任务、笔记、消息、撤销、提醒。
- **电脑端**只做三件事：提供流式 AI 接口、管理本地 AI 服务（模型启停/选择）、维护 adb 通道。无业务数据、无 dashboard。
- **AI 路由**：手机检测到电脑端在线（health 探测，30s 缓存）→ 用电脑端模型；否则用设置中配置的默认远程 API。两者都走 OpenAI 兼容协议 + SSE 流式。
- **零配置**：USB 物理通道即信任。电脑端只监听 loopback，手机端首次连通自动配对（`POST /v1/pair`），不输入 token。

## 1. 数据模型 v2（SQLite，DB v5）

### 1.1 messages —— 消息（数据源）

消息是**证据与上下文**，不是应用的主体。它只回答问题："这条信息从哪来、说了什么、重要吗、有没有衍生任务"。

```sql
CREATE TABLE messages(
  id TEXT PRIMARY KEY,
  package_name TEXT NOT NULL,          -- 来源应用包名；手动添加为 'manual'
  app_name TEXT,
  channel_id TEXT,
  conversation_title TEXT,             -- 会话标题（群名/联系人）
  sender TEXT,                         -- 拆分折叠通知后填充
  title TEXT NOT NULL,
  body TEXT NOT NULL,
  posted_at INTEGER NOT NULL,
  capture_type TEXT NOT NULL,          -- notification | manual | import
  import_source TEXT,                  -- 预留：wechat | qq | sms
  attachments TEXT NOT NULL DEFAULT '[]',
  content_hash TEXT NOT NULL UNIQUE,
  status TEXT NOT NULL DEFAULT 'pending',  -- pending | processed | archived
  priority TEXT NOT NULL DEFAULT 'none',   -- none | red | yellow | green | junk
  linked_task_id TEXT,                 -- 衍生任务（可空）
  created_at INTEGER NOT NULL
);
```

- `priority` 语义：**红=重要、黄=值得关注、绿=一般、junk=垃圾、none=未评估**。AI 处理时初判，用户可随时改。
- `status` 只管"是否流转过"：pending（未处理）→ processed（已评估，留在列表）→ archived（归档，移出主列表）。与 v1 的 done 合并进 archived。
- 消息**没有"完成"态**——完成是任务的概念。

### 1.2 tasks —— 任务（应用主体之一）

```sql
CREATE TABLE tasks(
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,                 -- 宽度约束见 §7
  description TEXT,
  kind TEXT NOT NULL,                  -- point | range
  start_at INTEGER,                    -- 可空 = 无时间任务（不定时）
  end_at INTEGER,                      -- kind=range 时非空
  priority TEXT NOT NULL DEFAULT 'normal',  -- important | normal | minor
  is_annual INTEGER NOT NULL DEFAULT 0,     -- 年度重复任务（每年重复展示）
  source_message_id TEXT,              -- 来源消息（可空，任务可独立存在）
  parent_id TEXT,                      -- v2.2：父任务（可空，仅一级子任务）
  status TEXT NOT NULL DEFAULT 'active',    -- active | done | archived
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE INDEX idx_tasks_start ON tasks(start_at);
CREATE INDEX idx_tasks_status ON tasks(status);
```

- 五类派生展示（由 kind + 时间得出，不落库）：时间点 / 时间点任务 / 时间段 / 时间段任务 / 普通任务。统一为任务实体，`kind` + `start_at/end_at` 可空覆盖全部五类。
- **时间尺度（time scale）**（v2.1，派生不落库，纯函数 `deriveTimeScale(startAt, endAt)`）：从大到小 **年度 / 季度 / 月度 / 整周 / 整日 / 定时 / 不定时**。推导链（"相邻" = 同一自然单位或紧邻的上一个/下一个）：
  1. 无开始时间 → **不定时**（唯一无时间尺度）；
  2. 起止（kind=point 时 end 视为 = start）在**同一天或相邻两天** → **定时**；
  3. 否则，在**同一自然周（周日起）或相邻两周** → **整日**；
  4. 否则，在**同一自然月或相邻两月** → **整周**；
  5. 否则，在**同一自然季度或相邻两季度** → **月度**；
  6. 否则，在**同一年或相邻两年** → **季度**；
  7. 否则 → **年度**。

  每个任务**恰好**有一个派生尺度（链上首次满足的档；"至少为 X" 即指该档）；每个任务至少属于一个尺度（无时间 → 不定时兜底）。手动标注尺度预留，本期不实现。
- **跨度不限**（v2.2）：允许跨度超过一年甚至多年的任务（落入年度尺度，由年度视图展示）。v2 初版"不允许跨度 ≥ 一整年"的限制取消。
- `is_annual`：年度**重复**任务（如"年度体检"），与派生尺度正交；在年度视图（每年一个节点）与待办"年度"页签逐年分节展示。
- **子任务**（v2.2，`parent_id` 可空）：
  - 约束：子任务尺度 ≤ 父任务尺度（同级或更小），且**有时间时其时间范围必须是父任务范围的子集**；只允许**一级**子任务（父任务本身不得再有 parent_id）；不定时子任务不受范围约束，但父任务不定时时子任务也必须不定时。
  - 设为子任务时若时间范围不符，弹三选对话框：**扩大父级任务时间范围**（父扩到包含子）/ **缩小子级任务时间范围**（子钳制到父范围内）/ **取消**。
  - 甘特图：子任务画在父任务**同一 y 坐标**（叠加于父的泳道槽位，用更小节点/更细线段区分），其余任务一律从上到下填补排开。
- 任务可以没有来源消息（`source_message_id` 可空）——手动创建与 AI 创建地位相同。

### 1.3 笔记三级

```sql
CREATE TABLE notebooks(
  id TEXT PRIMARY KEY, name TEXT NOT NULL, sort INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL
);
CREATE TABLE chapters(
  id TEXT PRIMARY KEY, notebook_id TEXT NOT NULL REFERENCES notebooks(id),
  name TEXT NOT NULL, sort INTEGER NOT NULL DEFAULT 0, created_at INTEGER NOT NULL
);
CREATE TABLE notes(
  id TEXT PRIMARY KEY, chapter_id TEXT NOT NULL REFERENCES chapters(id),
  title TEXT NOT NULL, content TEXT NOT NULL DEFAULT '',
  content_format TEXT NOT NULL DEFAULT 'plain',   -- plain；markdown 预留
  created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL
);
```

### 1.4 撤销队列（内存，不落盘）

见 §6。重启后队列清空是可接受的——撤销窗口只有 10 秒。

### 1.5 迁移

- **v3 → v4**：只增不删，旧表（raw_messages / structured_items）原样保留一个版本周期：

| 旧 | 新 |
|---|---|
| raw_messages | → messages（status 保留；done→archived；priority 由 structured_items 的 priority 映射：P0/P1→red，P2→yellow，P3→green） |
| structured_items (category=todo/schedule) | → tasks（time.kind=point→kind=point+start_at；range/deadline→对应区间；payload.priority→三档映射；rawMessageIds[0]→source_message_id） |
| structured_items (category=note) | → 默认笔记本「导入」的章节「AI 笔记」下的 notes |
| structured_items (其他) | 不迁移实体，仅在 messages.priority 上留评估结果 |

- **v4 → v5**（v2.2）：`ALTER TABLE tasks ADD COLUMN parent_id TEXT`。无数据搬迁。

## 2. 模块一：日程（首屏，核心）

四个粒度视图共用一套渲染思想：**泳道/时间轴 + 节点/线段 + 名称层**，全部 CustomPainter 自绘 + GestureDetector 交互。

- **标题**（v2.1）：AppBar 标题不显示"日程"，显示当前粒度的时间尺度——年度视图显示轴覆盖区间（如 `2020–2039`）、年视图 `2026年`、月视图 `2026年10月`、日视图 `2026年10月13日（周二）`，随视图内翻页/下钻实时更新。
- **尺度过滤**（v2.2）：每个视图只显示对应尺度的任务（尺度定义见 §1.2）：
  | 视图 | 显示的尺度 |
  |---|---|
  | 年度视图 | 年度（+ is_annual 每年节点） |
  | 年视图 | 季度、月度、整周 |
  | 月视图 | 整周、整日 |
  | 日视图 | 定时 |

  不定时任务无时间，不进任何日程视图。
- **底部任务列表板块**（v2.2）：年/月/日视图下方单开一个列表板块，UI 照搬待办页行设计（勾选框、优先级点、尺度徽标、时间摘要、点按进编辑器）：
  - 年视图下：**当前年度任务**（尺度=年度 且与当前年有交集）；
  - 月视图下：**当前月度任务**（尺度=月度 且与当前月有交集）；
  - 日视图下：**当前整日任务**（尺度=整日 且与当前日有交集）；
  - 年度视图无底部板块。

### 2.1 年度视图（v2.2 新增）

- 结构与日视图同构：横向**年份轴** + 节点/线段 + 45° 斜向上名称层（虚线指引规则同日视图 §2.4）。
- 横轴默认覆盖当前年前后各若干年（如 ±10 年），横向滚动翻页，捏合缩放（刻度档：1 年 / 5 年 / 10 年每格，选取规则同 §2.4 的"≥64dp 最密档"思想）。
- 任务表示：尺度=年度的任务——单年内的为节点，跨年的为带端点线段；**当前年一条高亮竖带**。
- `is_annual` 年度重复任务：其时间映射到轴上每年各画一个小节点。
- 交互：拖拽调整粒度=年（吸附年界），无跨度上限；点击节点/线段/名称 → 任务编辑器（§7）；点击某个年份格 → 下钻该年的年视图。

### 2.2 年视图

- 布局：4 行（每季度一行）× 3 块（每块一个月）。月块等宽，块间距固定。
- 泳道：每月块内 3 条水平泳道，**月与月之间上下对齐**；从上到下依次为 **红(important) → 黄(normal) → 绿(minor)**。
- 显示范围（v2.2）：只显示尺度为**季度/月度/整周**的任务。
- 任务表示：
  - 月级任务（起点终点同月或仅指定月）→ 该月泳道上的**节点**（圆点）。
  - 跨月任务 → **带端点节点的线段**，跨越其覆盖的月块。
  - 任务名称在节点/线段**右侧横向**显示（放得下才显示，放不下省略）。
  - **当前月高亮**（底色 + 边框）。
- 填充算法（泳道内，纯函数 `layoutYearLane(tasks)`）：
  1. 泳道内任务按开始时间先后排序；
  2. 单条泳道纵向可叠多个"槽位"：任务按开始时间从上到下填补空位；
  3. 若某槽位被更早的跨月任务线段占据，**跳过该位置继续往下排**（跨月任务优先占位）；
  4. 跨月任务起点或终点不在当前年：端点处画**延伸样式**（斜切箭头指出边界），但**不为跨年保留槽位**——下一年的该任务直接排其优先级泳道的最上面槽位。
- 交互：
  - 点击月块 → 下钻到该月的月视图；上跳图标 → 返回年度视图。
  - 拖拽节点/线段调整时间：**粒度=月**（吸附月边界），区间任务拖中段平移、拖端点改起止；**跨度不限**（v2.2，跨度超一年将落入年度尺度，转由年度视图展示）。
  - 点击节点/线段/名称 → 任务编辑器（§7）。

### 2.3 月视图

- 布局：4–6 行（每周一行，覆盖当月），每行 7 列（**星期日 → 星期六**）。
- 显示范围（v2.2）：只显示尺度为**整周/整日**的任务。
- 结构是年视图的"日级同构"：每个日格内沿用节点/线段 + 泳道（高度受限时只画节点，名称层省略）；跨日任务画跨格线段；**今天高亮**。
- 点击日格 → 下钻日视图；拖拽粒度=日；其余同年视图。

### 2.4 日视图

- 显示范围（v2.2）：只显示尺度为**定时**的任务。
- 横轴 00:00–24:00，**比例尺捏合缩放、连续跟手**（v2.1 修订）：
  - 缩放为无级连续映射 `pxPerMinute`，以**双指焦点对应的时间点**为锚（焦点下的时间不动），无档位跳变感；
  - 范围：最小 = 24h 恰好铺满可视宽；最大 = 每 5 分钟 ≥ 48dp；
  - 惯性/回弹可选，钳制在范围内。
- **刻度动态调整**（v2.1 修订，替代固定 30 分钟点）：
  - 标注间隔候选档：**5 / 15 / 30 / 60 / 120 分钟**，按当前 `pxPerMinute` 选「相邻标注间距 ≥ 64dp」的最密档；
  - 主刻度 = 标注间隔（长刻度线 + 竖格线），次刻度 = 下一更密档（短刻度线，间距过挤时省略）；
  - **时间标注斜 45° 向上**（旋转 -45° 文本，锚在刻度点，向右上延伸），过挤时按 2 的幂隔一个显示。
- 任务表示：时间点任务=节点；时间段任务=**带断点的线段**（端点为断点方块）；**当前时间 = 一条高亮竖线**（定时器每分钟重绘）。
- 名称层（甘特图上方独立区域，45° 斜向上文本带）：
  - 仅当比例尺达到"每 5 分钟一个节点且每个名称文本都放得下"时才显示名称；
  - 时间点任务：从节点向上引**虚线**指向其斜文本名称；
  - 时间段任务：在其时间范围内**尽量找靠前的名称空位**，垂直向上连一条虚线到线段；
  - 名称空位分配是纯函数 `assignDayNames(tasks, scale)`：按开始时间升序，斜文本带从下往上、从左往右试放，与已放置的文本框（旋转 45° 的 OBB）做碰撞检测，找到即放；**找不到空位的任务不显示名称**（节点/线段仍在）。
- 交互：拖拽节点/线段调整时间，**粒度=5 分钟**（吸附）；点击 → 任务编辑器；上跳图标回月视图。

### 2.5 视图间导航

```
年度视图 --点年格--> 年视图 --点月块--> 月视图 --点日格--> 日视图
   <--上跳按钮--      <--上跳按钮--      <--上跳按钮--
```

每个视图顶部：粒度切换图标组（年度/年/月/日，等宽分段控件，见 §9）+ 今天按钮 + 上跳按钮（在最细粒度时可回跳）。标题见本节开头规则。

## 3. 模块二：待办（v2.1：按时间尺度分页）

顶部**尺度页签**（等宽段、横向可滚动、选中只改底色，遵守 §10 分段控件规范），从大到小：

**年度 / 季度 / 月度 / 整周 / 整日 / 定时 / 不定时 / 已完成 / 已归档**

| 页签 | 内容 | 排序 |
|---|---|---|
| 年度 | 派生尺度=年度 的 active 任务；其后接 **is_annual 逐年分节**（从今年起 5 年，即使该年无任务也显示年份标题） | 开始时间 |
| 季度 / 月度 / 整周 / 整日 / 定时 | 对应派生尺度的 active 任务 | 开始时间 |
| 不定时 | 无开始时间的 active 任务（即原"我的待办"） | 优先级→创建时间 |
| 已完成 | status=done（24h 内置顶，其余沉底） | 完成时间倒序 |
| 已归档 | status=archived | 归档时间倒序 |

- 行内：勾选框（完成/取消完成）、三色优先级点、**尺度徽标**、时间摘要、来源消息角标（点按跳转消息）、**子任务缩进标识**（v2.2：子任务在父任务行下缩进显示，父任务可折叠）。
- 点按行 → 任务编辑器（§7）；新增按钮 → 空白任务编辑器。
- 完成 → 撤销 SnackBar；归档 → 撤销 SnackBar（撤销见 §6）。
- 任务的尺度随时间编辑自动变化（派生），编辑器中只读展示当前尺度。

## 4. 模块三：笔记

- 三级导航：笔记本列表 → 章节列表 → 笔记编辑器（纯文本，`content_format=plain`，Markdown 预留）。
- 每层可增删改排序；删除笔记本/章节为级联删除（进撤销队列的复合操作）。

## 5. 模块四：消息（数据源）

### 5.1 消息列表

- 排序：**未处理(none/pending) → 红 → 黄 → 绿 → 垃圾**，组内按 posted_at 倒序；每组有吸顶分组头（可折叠）。
- 行标记（左端）：
  - 有空心圆点 = 未处理；
  - 颜色圆点 = 已评估（红/黄/绿）；
  - 有任务关联 = 圆点右侧叠加小角标；
  - 垃圾 = 整行**灰色消息块**（降饱和、划线标题）。
- 左滑 → **块状菜单**（圆角色块按钮，非列表）：

| 状态 | 菜单项 |
|---|---|
| 未处理 | 自动处理（AI 评估+可选生成任务） / 创建任务 / 标记垃圾 / 归档 |
| 已处理 | 重新处理（AI 再评） / 创建任务或删除任务（视有无 linked_task）/ 标记垃圾 / 归档 |
| 垃圾 | 移出垃圾 / 归档 |
| 已归档（归档页） | 取出 / 删除 |

- **左滑手势验收标准**（v2.1 修订，替换原自实现手势——原实现难以触发且命中区域有缺陷）：
  1. 轻扫（位移 ≥ 40dp 或快速甩动）即可展开，松手吸附到全展/全关，无中间卡顿态；
  2. 展开后动作块点击**必触发**（不得被行内容的手势区域吞掉）；
  3. 展开后点击行内容或反向轻扫即收起；
  4. 多行可同时各自独立展开/收起，互不干扰；
  5. 有对应 widget 回归测试。
  实现优先评估成熟库（如 flutter_slidable），达不到以上标准才自研。
- 筛选器行：状态分组多选 + 应用筛选（统一 Chip 行，见 §9）；多选模式：
  - 长按进入多选；底部出现**图标按钮条**；菜单项可用性 = 所选消息**能力交集**（如混选"垃圾+非垃圾"时"标记垃圾/移出垃圾"均禁用，"归档"可用）。
- 已归档消息独立页签，左滑=取出/删除，多选同上。
- 「导入」入口（微信/QQ/短信）：占位按钮 + "即将支持"提示，协议字段（capture_type=import, import_source）已预留。

### 5.2 消息与任务联动

- 创建任务：以消息标题为默认任务名、正文为描述进入编辑器，保存后 `messages.linked_task_id` 与 `tasks.source_message_id` 互链。
- 删除任务（从消息菜单）：删除 linked_task（进撤销队列）。
- AI 自动处理：产出 priority + 可选任务草稿；草稿需用户在结果面板一键确认才落 tasks（不静默建任务）。

## 6. 撤销系统

- **UndoService（内存单例）**：队列元素 = { id, label, execute() 的逆操作闭包, enqueuedAt }。
- 规则：
  1. 任何数据变更操作**执行成功后**将其逆操作入队，TTL=10 秒，过期丢弃；
  2. 撤销 = 弹出**最晚入队**的有效项并执行其逆操作（后来者先撤）；
  3. 被撤销的操作从队列**永久移除**（不做重做）；
  4. 新操作入队时若队列中已有更晚的分支点（即发生过撤销后的新操作），丢弃另一分支——实现为：撤销只弹栈、入队即截断，天然满足"分叉丢弃另一分支"；
  5. 批量操作（多选）作为一个**复合逆操作**入队，撤销时整体回滚。
- UI（v2.1 修订 SnackBar 行为）：
  - 撤销 SnackBar 文案"{label}"+「撤销」按钮，**时长 4 秒**、**不排队**——新操作立即 `hideCurrentSnackBar` 替换当前条（不叠加占用底部）；支持滑动关闭；
  - 轻提示（如"即将支持"）**时长 2 秒**；
  - 撤销队列 TTL 仍为 10 秒（Snackbar 收回后不再有点按入口，过期项自动丢弃——可接受的弱一致）。

## 8. AI 处理

### 8.1 路由（AiClient）

```
process(messages):
  if 电脑端 health 探测在线（30s 缓存） → POST /v1/process（adb 通道，自动配对 token）
  else → 设置中的默认远程 API（OpenAI 兼容 /chat/completions, SSE）
```

- 远程接口配置：多套 { name, baseUrl, apiKey, model }，设置页管理，选默认；电脑端条目自动生成只读（标注"已连接/未连接"）。

### 8.2 处理目标

对一批消息，AI 输出（每消息一条）：

```json
{
  "priority": "red|yellow|green|junk",
  "reason": "一句话理由",
  "taskDraft": { "title": "...", "description": "...", "kind": "point|range",
                 "startAt": "YYYY-MM-DDTHH:mm", "endAt": "...", "priority": "important|normal|minor" } | null
}
```

- 筛选重要 vs 垃圾是 AI 的**第一职责**（垃圾：营销、推广、无用系统提示等）；任务草稿是第二职责。
- 提示词仍由注册表/分类描述生成（沿用 v1 资产），但输出 schema 换成上面的精简结构；时间解析沿用"日期对照表 + 已过去顺延 + 本地时间字符串"策略。
- **v2.4 提示词规则**（两端逐条一致：mobile `services/ai_client.dart` `_buildSystemPrompt`，desktop `src/ai/evaluate.ts` `buildEvalSystemPrompt`）：结合来源应用/会话语境判断重要与垃圾；无明确时间的可执行事项省略 startAt/endAt（不定时任务）；值得留存备查的笔记类内容也给 taskDraft（priority=minor）；title ≤20 字符（中文按 2 计），细节进 description；多步骤事项只给主事项草稿，子步骤以换行列表写进 description。schema 无新增字段，startAt/endAt 可省略，两端解析均容忍缺失。

### 8.3 流式展示（v1）

- 电脑端 NDJSON 增加事件 `{"type":"token","messageId":"...","delta":"..."}`（provider 以 stream 模式调模型，边生成边透传）。
- 手机直连远程 API 时直接读 SSE delta。
- UI：处理中底部升起"AI 处理中"面板——当前消息标题 + **实时滚动的原始输出文本** + 已完成计数；完成后面板汇总"评估 x 条 / 垃圾 y 条 / 任务草稿 z 条"，用户逐条或批量确认。
- 可视化展示（时间线动画等）留后续版本。

#### 消息导入方案（预留，对应 v2.4-20）

目标：把微信/QQ/短信的历史消息导入 messages 表，纳入统一的消息-任务-AI 管线。

- **数据模型**：messages 表复用现有结构，`capture_type='import'`，新增 `import_source` 标记来源平台（wechat/qq/sms）；正文按现有 body 纯文本落库，会话名/群名填入 title，发送者填入 sender（无则空）。去重键沿用 content_hash（平台+会话+时间+正文哈希）。
- **格式解析**（按平台调研后实现，优先级：短信 > QQ > 微信）：
  - 短信：系统 SMS 数据库导出（content://sms，需 READ_SMS 运行时权限，导入页内引导授权），字段直接映射。
  - QQ：仅支持用户手动导出的文本/聊天记录文件（如 .txt/.bak），按「时间 发送者\n正文」段落切分解析；格式变体用正则模板表，解析失败的行计入错误报告。
  - 微信：无官方导出。方案 A（首选）：解析用户从电脑端微信备份/第三方工具导出的文本文件；方案 B（调研）：root/无障碍读取本地数据库（EnMicroMsg.db，需 SQLCipher 密钥派生）——仅做可行性调研，不承诺实现。
- **UI 入口**：消息页右上角导入图标 → 二级页（选来源平台 → 选文件/授权 → 解析预览（条数/时间范围/错误行数）→ 确认导入）。
- **进度与错误**：导入在 isolate 中分批（500 条/批）事务写库；进度条显示已解析/总数；解析失败行收集为报告（导入完成后可查看/导出）；重复消息（content_hash 命中）静默跳过并计入「跳过 n 条」。
- **与 AI 管线关系**：导入消息默认不自动触发 AI 处理（与实时捕获一致，由用户手动发起）。

### v2.5（2026-10-15）

真机测试反馈批：5 个 bug 修复 + 任务详情交互统一。DB schema 不变。

#### Bug 修复

1. **fling 惯性滚动只第一次有效**（§2.1、§2.3）：根因——年度/日视图用 `SingleTickerProviderStateMixin` 却每次 fling 都新建 `AnimationController`，mixin 的 ticker 槽位创建后不复位，第二次 `createTicker` 在 debug 下抛断言，fling 静默失效。修法：两处视图改 `TickerProviderStateMixin`；撞边界时不再在动画值通知回调里 dispose 自身控制器（改为 stop + 帧末回收）。回归测试 `test/fling_scroll_test.dart`。
2. **月视图负数年份（-85354）**（§2.2）：根因——v2.4 可变行高改造混用两套坐标系：`itemBuilder` 按索引空间映射，而 `initialScrollOffset`/`_jumpToMonth`/`_reportWindow` 用像素累计偏移换算，首屏即落在公元前 8 万年。修法：坐标系统一为索引空间——恢复恒定 `_itemExtent`（= 标签高 + 头部高 + 6 行格子高），定位换算复用与年视图同一套 `itemIndexForUnit`/`unitIndexForItem`；每月网格行数仍按当月实际（4~6 行，无整行灰格），行数不足的月份 item 内下方留白。删除像素累加高度表。边界测试 `test/month_view_test.dart`（2000–2030 行数全覆盖、首屏当前月、快速连滑、scrollTo 基准月/远端月、scrollToTask）。
3. **年视图跨出年界的任务不再画箭头端点**（§2）：`extendsBefore/After` 的任务线段直接截断在网格边界，不画任何端点标记；startMonth/endMonth 本就由 layoutYearLane 钳在年内。
4. **年度/日视图线段端点方块→圆点**（§2.1、§2.3）：与时间点任务节点同半径（3.5/5.0），全视图端点样式统一为圆点。
5. **消息抓取失效防御**（§4、§5）：v2.4 把 `getTasks(done)` 并入消息页 reload 的 `Future.wait` 关键路径，任一失败列表永停「加载中」——拆为关键路径（messages+sources）与独立 try/catch 的尽力路径（doneTaskIds、listenerEnabled）。另：消息页顶部新增「监听权限丢失」横幅（含去授权入口）；Kotlin 侧 getInstalledApps/getAppIcon 后台线程包 try/catch 保证 result 必回调；`AppFilterConfig.allows` 镜像 Kotlin 三态语义（whitelist/blacklist/默认全放行）并配单测。

#### 任务详情交互统一

目标模型：任务详情不再是底部弹出抽屉，日程页与待办页共用同一内嵌 `TaskDetailPanel`（新增可选 `onClose` 返回按钮），选中态唯一（图表选中描边 = 列表行高亮）。

- **日程页底部面板双模式**（§2）：列表模式（默认）= 可视范围 ∩ 尺度集合的任务列表；详情模式 = TaskDetailPanel。图表点击任务 → 只选中：图表描边 + 底部列表滚动到该行高亮（`Scrollable.ensureVisible`），不再直接开详情；选中任务不在列表时给 2 秒提示。列表行点击 → 进详情模式。详情返回按钮/取消选中（点空白）/切换粒度/下钻 → 回列表模式；编辑删除任务 → 清选中并退出详情。拖拽逻辑不变。
- **待办页内嵌详情**（§3）：取消 `showModalBottomSheet` 详情；点击任务行进入详情模式（页面下部内嵌同一 TaskDetailPanel 替换 PageView），返回按钮/切换或滑动页签回列表模式；reload 后从全部列表刷新详情中的任务，任务消失（删除/归档流转）自动退出详情；详情中点父/子任务 → 退出详情、切页签并高亮目标行（复用 v2.3 跳转定位）。
- **消息页不动**：消息条目交互不涉任务详情面板。
